The FTC Robot Controller SDK includes a rich library of sample OpModes covering everything from bare-bones structure examples to advanced autonomous navigation with gyro correction and computer vision. Before you write a single line of your own code, spending time reading through these samples is one of the most effective ways to understand how the SDK works — they are the official reference implementations for every major hardware and programming pattern.

## Where samples live

All samples are located at:

```
FtcRobotController/src/main/java/org/firstinspires/ftc/robotcontroller/external/samples/
```

This folder ships read-only as part of the SDK module. You should **never edit files inside the `samples` folder directly** — any changes you make there will be overwritten the next time you update the SDK.

<Note>
  Always copy samples into your **TeamCode** package before modifying them. In Android Studio, right-click the sample class → **Copy** → navigate to your TeamCode package → **Paste**. Android Studio automatically renames both the file and the class declaration to match the name you choose, and updates the package statement. This is the only safe way to work with samples.
</Note>

## The `@Disabled` annotation

Every sample in the SDK includes the `@Disabled` annotation directly above the class declaration:

```java
@Autonomous(name="Robot: Auto Drive By Encoder", group="Robot")
@Disabled
public class RobotAutoDriveByEncoder_Linear extends LinearOpMode {
```

This prevents the sample from appearing in the Driver Station OpMode list. When you copy a sample to TeamCode and are ready to test it on the robot, **remove or comment out the `@Disabled` line**. Forgetting to do so is one of the most common reasons a new OpMode doesn't show up on the Driver Station.

## Naming conventions

Sample class names follow a structured naming convention that tells you exactly what a sample does before you open it. The name is composed of a **prefix**, a **topic or action**, and a **suffix** indicating OpMode type.

### Prefix: what category is it?

| Prefix | Meaning |
|---|---|
| `Basic` | A minimally functional OpMode illustrating the skeleton/structure of a particular style of OpMode. These are bare bones examples — a good first read. |
| `Sensor` | Shows how to read a specific sensor. Not intended to drive a robot; just shows the minimal code to read and display sensor values. |
| `Robot` | Assumes a simple two-motor differential drive base. Used for common baseline driving OpModes or to demonstrate navigation with sensors. |
| `Concept` | Illustrates one specific function or concept (state machines, bulk reads, rumble feedback, etc.). Each Concept sample tries to demonstrate only a single idea so they are easy to find by name. |

### Class name patterns

After the prefix, the rest of the name is constructed as follows:

- **Sensor samples:** `Sensor – Company – Type`  
  *Example: `SensorBNO055IMU` → Bosch BNO055 IMU*

- **Robot samples:** `Robot – Mode – Action – OpModeType`  
  *Example: `RobotAutoDriveByEncoder_Linear` → Autonomous, drives by encoder, LinearOpMode*

- **Concept samples:** `Concept – Topic – OpModeType`  
  *Example: `ConceptTensorFlowObjectDetection` → TensorFlow object detection concept*

### Suffix: which OpMode base class?

| Suffix | Base class | When to use |
|---|---|---|
| `_Linear` | `LinearOpMode` | Sequential, top-to-bottom code. Best for autonomous. Also works for TeleOp. |
| `_Iterative` | `OpMode` | Callback-based. The SDK calls `loop()` repeatedly. Familiar if you know Arduino-style programming. |

Samples without a suffix (e.g., `RobotHardware`) are helper classes, not runnable OpModes.

## How to copy a sample to TeamCode

<Steps>
  <Step title="Locate the sample in Android Studio">
    In the **Project** panel, expand `FtcRobotController → src → main → java → org.firstinspires.ftc.robotcontroller.external.samples`. Find the class you want to use.
  </Step>
  <Step title="Copy the class">
    Right-click the class file → **Copy** (or press `Ctrl+C` / `Cmd+C`).
  </Step>
  <Step title="Navigate to TeamCode">
    Expand `TeamCode → src → main → java → org.firstinspires.ftc.teamcode`.
  </Step>
  <Step title="Paste and rename">
    Right-click the `teamcode` package → **Paste**. Android Studio will prompt you for a new class name. Enter a descriptive name for your OpMode (e.g., `MyAutoEncoder`). Android Studio automatically updates the class declaration, constructor name, and package statement.
  </Step>
  <Step title="Remove @Disabled">
    Open the newly created file. Find the `@Disabled` annotation and delete it (or comment it out with `//`). Save the file.
  </Step>
  <Step title="Build and deploy">
    Click **Build → Make Project** to verify there are no compile errors, then deploy to the Robot Controller and check that your OpMode appears in the Driver Station list.
  </Step>
</Steps>
